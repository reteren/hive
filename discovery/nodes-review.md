## 1. Введение и концептуальный фундамент Mastermind

Проект **Mastermind** (в кодовой базе `hive`) представляет собой амбициозный гибрид четырех систем:
1. **Obsidian (50%):** Свободная база знаний, markdown-форматирование, гиперссылочный граф, локальное хранение, атомарные заметки.
2. **Schedule Program / Scheduler (25%):** Календарное планирование, повторяющиеся задачи, дедлайны, таймеры, списки дел и реактивные напоминания.
3. **Node Editor (25%):** Визуальное программирование логики, потоки сигналов, условия, триггеры, связывание объектов на бесконечной координатной плоскости.
4. **Blender UX (эргономический ориентир):** Пространственная плотность, круговые (radial) меню (кнопка `X`), мгновенный доступ к инструментам по «горячим» клавишам (`C`, `V`, `D`, `T`, `M`, `WASD`), навигация мышью (zoom колесиком, pan средней кнопкой мыши) и контекстное разрешение коллизий (Photoshop-style выбор перекрывающихся слоев).

Главное концептуальное отличие Mastermind от существующих нодовых редакторов (Blender Geometry Nodes, Unreal Blueprints, ComfyUI) и менеджеров заметок (Obsidian Canvas, Heptabase, Miro):  
**Холст в Mastermind — это не просто статическая доска для записок и не абстрактный конвейер обработки данных, а многоуровневая (с этажами `Floor`), пространственно зонированная (`Zone`), саморегулирующаяся операционная среда личной продуктивности и мышления с центральным ядром («ME»).**

## 2. Фундаментальная таксономия связей: Триптих графа Mastermind

Одна из главных архитектурных ловушек в описании `hive.md` — восприятие «линии» как универсальной сущности. Если связать две ноды обычной стрелкой, что именно передается: смысловая ассоциация, поток данных или импульс к выполнению задачи?

В качестве одной гипотезы для исключения хаоса предлагается разделение на **три типа связей** и **внутренние сокеты**:

```
                         ┌──────────────────────────────────────────────┐
                         │              ХОЛСТ MASTERMIND                │
                         └──────────────────────┬───────────────────────┘
                                                │
       ┌────────────────────────────────────────┼────────────────────────────────────────┐
       ▼                                        ▼                                        ▼
┌──────────────────────┐             ┌──────────────────────┐             ┌──────────────────────┐
│    KNOWLEDGE EDGE    │             │   EVENT/SIGNAL EDGE  │             │    DATA FLOW EDGE    │
│ (Смысловая ассоциация│             │(Импульс исполнения / │             │  (Поток значений /   │
│   стиля Obsidian)    │             │   Control Flow)      │             │   реактивный DAG)    │
├──────────────────────┤             ├──────────────────────┤             ├──────────────────────┤
│ • Клавиша: C или V   │             │ • Активация триггеров│             │ • Входы/выходы типов:│
│ • Градиент или пунктир│            │ • Time -> IF -> Action│            │   String, Int, Bool  │
│ • Без сайд-эффектов  │             │ • Строгий лимит стека│             │ • Строгий DAG без    │
│ • Циклы РАЗРЕШЕНЫ    │             │ • Циклы только через │             │   обратных петель    │
│   (онтология мысли)  │             │   Wait/Timer/Gate    │             │ • Чистые вычисления  │
└──────────────────────┘             └──────────────────────┘             └──────────────────────┘
                                                │
                                                ▼
                                     ┌──────────────────────┐
                                     │  SOCKETS / MODIFIERS │
                                     │(Внутренние свойства) │
                                     ├──────────────────────┤
                                     │ • Не провода на поле!│
                                     │ • Бейджи, рамки      │
                                     │ • Предотвращают      │
                                     │   «спагетти-ноды»    │
                                     └──────────────────────┘
```

### 2.1. Knowledge Edge (Смысловая связь)
- **Визуализация:** Плавная градиентная линия между цветами нод (клавиша `C`) либо пунктирная слабая связь (клавиша `V`).
- **Семантика:** «Заметка А концептуально связана с Заметкой Б». Линия не производит вычислений, не активирует скрипты, не передает сигналы таймера.
- **Циклы:** Допустимы в любых комбинациях (A → B → C → A). Граф знаний в человеческом мозге фрактален и замкнут, запрещать циклы здесь бессмысленно.

### 2.2. Event / Signal Edge (Шина исполнения и импульсов)
- **Визуализация:** Жирная контрастная линия с анимированным импульсом при срабатывании («pulse wire»).
- **Семантика:** Дискретный триггер: «Сработало время T», «Пользователь нажал кнопку Confirm», «Задача завершена».
- **Рантайм — предложение:** рассмотреть ограничение глубины каскада; `128` шагов приведены только как обсуждаемый пример, а не утвержденное значение.

### 2.3. Data Flow Edge (Шина типизированных данных)
- **Визуализация:** Тонкая цветная линия, цвет которой жестко кодирует тип данных:
  - Зеленый: логический (`Boolean`)
  - Синий: целое/дробное число (`Number`)
  - Желтый: текст (`String` / `Markdown`)
  - Оранжевый: контекст объекта/пространственный ID (`SpatialRef`)
  - Фиолетовый: список/коллекция (`List<T>`)
- **Семантика:** Передает значение из выходного порта одной ноды во входной порт другой. Вычисляется по требованию (pull-based) или реактивно (push-based) только в пределах ациклического графа (DAG).

## 3. Архитектурное разделение: Нода vs Режим vs Свойство vs Пресет

В черновике `hive.md` прослеживается тенденция превращать любую микро-функцию в физическую ноду на холсте. Например:
- `Importants node`: микро-нода, которая «ничего не делает кроме визуала», вешает цветную рамочку (basic, medium, important, immediately, 100% RGB) и может вставляться внутрь другой ноды или соединяться однонаправленной линией.
- `Message node`: «не совсем полноценная нода», которая настраивает тип, силу, размер и количество уведомлений и вставляется внутрь `repeat` или `IF`.

Если реализовать их как отдельные объекты на поле, холст моментально превратится в нечитаемое «спагетти» из десятков микро-прямоугольников, мешающих обзору карты.

### 3.1. Трехуровневая модель сущностей

1. **Canvas Node (Полноценная нода холста):**
   - Имеет собственные мировые координаты `(x, y)`, ширину, высоту, принадлежность этажу (`Floor`) и зоне (`Zone`).
   - Имеет уникальный `UUID` и отображается в древовидном списке объектов левой панели (клавиша `T` / Layout).
   - Обладает жизненным циклом и портами ввода-вывода (Signal / Data).
   - *Примеры:* `Markdown Note`, `Task Entity`, `Cron Schedule`, `IF Condition Gate`, `Prompt Dialog Gate`, `Portal Bridge`.

2. **Node Modifier / Internal Socket (Внутренний модификатор / Слот ноды):**
   - Не существует в свободном пространстве холста; физически встраивается в тело родительской ноды (как слоты модификаторов в Blender или карточки чеклиста внутри задачи).
   - Не имеет собственных координат на холсте, перемещается вместе с родителем.
   - *Примеры:* 
     - **Importance Badge** (переключатель важности: Basic / Medium / Important / Immediately / 100% Rainbow).
     - **Subtask Checklist** (список вложенных пунктов `[ ]`).
     - **Notification Emitter** (конфигурация звонка/пуша прямо в теле ноды задачи).

3. **Node Properties & Inspector Presets (Свойства и пресеты инспектора):**
   - Настройки, отображаемые в контекстном меню ПКМ или боковой панели атрибутов: цвет фона ноды, HEX-подсветка, тайм-аут ожидания, порог срабатывания.
   - Не занимают полезную площадь рабочего стола.

## 4. Семантика ключевых механизмов: Tasks, Time, IF, Action, Bridge

### 4.1. Семантика задач (Task Semantics)

Задача в Mastermind — это состояние намерения, обладающее жизненным циклом:

```
 ┌──────────┐      Start      ┌─────────────┐     Wait Dep / Gate     ┌─────────────┐
 │  DRAFT   │ ──────────────> │ IN PROGRESS │ ──────────────────────> │   BLOCKED   │
 └──────────┘                 └──────┬──────┘                         └──────┬──────┘
       ▲                             │                                       │
       │ Reset                       │ Complete                              │ Unblock
       │                             ▼                                       ▼
 ┌─────┴────┐     Snooze      ┌─────────────┐                         ┌─────────────┐
 │ SNOOZED  │ <────────────── │  COMPLETED  │                         │    READY    │
 └──────────┘                 └─────────────┘                         └─────────────┘
```

1. **Событийные триггеры задачи:** Каждая нода задачи генерирует сигналы в шину:
   - `OnActivated`: Задача взята в работу.
   - `OnCompleted`: Задача помечена выполненной.
   - `OnFailed`: Дедлайн просрочен / отменена.
   - `OnBlocked`: Появилась невыполненная зависимость.
2. **Агрегация в Маяках (`Beacon`):**
   - Маяк рекурсивно сканирует свое поддерево (ноды, связанные прямыми стрелками `C`).
   - Маяк динамически вычисляет: `% выполнения задач`, `сумму открытых задач`, `ближайший дедлайн`, `общий объем слов`.

### 4.2. Семантика времени (Time Semantics)

Время в гибридной системе делится на два фундаментальных класса:
1. **Абсолютное время (Wall Clock):**
   - «Сработать 15 октября 2026 года в 14:00».
   - «Срабатывать каждый понедельник в 09:00» (Cron-стиль).
   - Генерация единичного импульса при наступлении системного времени Windows.
2. **Относительное время (Monotonic Timer & Intervals):**
   - «Отсчитать 25 минут работы (Pomodoro)».
   - «Подождать 5 минут после подтверждения» (`Wait Node`).
   - «Повторять каждые N часов после завершения предыдущей итерации» (*Floating Repeat*, в отличие от жесткого *Fixed Cron*).

### 4.3. Семантика логики (IF / Condition Semantics)

Узел `IF` не должен ограничиваться простой проверкой «прошло ли время»:
- **Вход импульса (`Trigger`):** Момент, когда условие должно быть вычислено.
- **Входы условий (`Condition Inputs`):** Логические выражения (`Task.is_done`, `Count > 5`, `Current_Hour >= 18`).
- **Выходные импульсы (`True / False`):**
  - При `True` импульс идет по зеленому каналу.
  - При `False` импульс идет по красному каналу (ветка `Else`).
- **Семантика сопоставления с сообщением (Message Match):** Если `IF` подключен к узлу интерактивного ввода, он может проверять текст ответа пользователя (регулярное выражение, ключевые слова, выбор одной из кнопок).

### 4.4. Семантика действий (Action Semantics: Human Gate vs System Action)

Отчет предлагает обсудить разделение действий на два подтипа:
1. **Интерактивные шлюзы (Human-in-the-Loop Gates):**
   - Требуют участия человека для продолжения потока исполнения.
   - При срабатывании открывают модальное окно или системный тост в Windows с вариантами («Да/Нет», поле ввода заметки, кнопка «Напомнить через 5 минут»).
   - **Состояние ожидания — предложение:** возможное состояние `Awaiting_Human_Input` могло бы переживать перезапуск, но пользователь пока не определил, нужно ли это, что именно сохранять и когда ожидание истекает.
2. **Автоматические действия системы (System Actions):**
   - Не требуют ожидания: выполняются мгновенно за 1 тик рантайма.
   - *Примеры:* Смена цвета целевой ноды на красный, телепортация камеры на заданные координаты или маяк, воспроизведение звукового файла `.wav`, отправка уведомления в трей Windows, инкремент числового счетчика.

### 4.5. Семантика этажей и Bridge Node (Spatial Topology)

В `hive.md` указано:
> «bridge node — нода которую нельзя ставить на этажи. так как она служить фактически мостом между этажами. ты можешь поставить её только на флор 0... входная нода с 3 этажа, выход на 5 этаже... так же как телепортер...»

#### Критический анализ и альтернативы исходной концепции Bridge:
1. **Проблема переполнения этажа 0:** Если заставлять пользователя ставить все мосты на нулевой этаж, базовый уровень быстро превратится в «свалку технических переходников», где переплетаются сотни проводов между всеми существующими зданиями.
2. **Альтернатива для обсуждения — Двусторонние Порталы (Portal Sockets / Shafts):**
   - Мост состоит не из одной ноды на этаже 0, а из **парных пространственных терминалов** (`Bridge Ingress` на этаже 3 и `Bridge Egress` на этаже 5).
   - Либо это вертикальная **«Шахта» (Elevator Shaft)**, которая пронизывает выбранные этажи в одних и тех же координатах `(X, Y)`.
   - Внутри шахты сигнал и камера перемещаются мгновенно по схеме внутренней адресации `hive://building_A/floor_5/node_42`.
3. **Локальный фокус здания против глобального среза:**
   - В `hive.md` сказано, что переход на этаж 3 глобально переключает все этажи во всех зданиях холста.
   - *Неутвержденная альтернатива:* обсудить поддержку двух режимов:
     1. **Building Focus Mode:** При переключении этажа колесиком (`Alt + Wheel`) меняется только здание под курсором. Этот режим не назначается по умолчанию без ответа пользователя.
     2. **Global Strata Mode:** Исходное глобальное правило можно сохранить как основной или дополнительный режим — выбор остается за пользователем.

### Семейство 1: Control Flow & Routing (Логика и управление потоком)

#### 1.1. `Logic_MultiGate` (Многовходовой логический шлюз)
- **Назначение:** Реализация сложных логических формул булевой алгебры (AND, OR, XOR, NAND, NOR).
- **Входы:** `Signal: Eval`, `Data: A (Bool)`, `Data: B (Bool)`, `Data: C (Bool, optional)`.
- **Выходы:** `Signal: OnTrue`, `Signal: OnFalse`, `Data: Result (Bool)`.
- **Свойства:** Выбор операции из выпадающего списка (`AND / OR / XOR / MAJORITY`).
- **Пример:** Срабатывает `OnTrue`, только если задача «Сдать отчет» выполнена И время больше 18:00.

#### 1.2. `Flow_SwitchCase` (Селектор веток по значению)
- **Назначение:** Маршрутизация управляющего импульса по N направлениям в зависимости от текстового или числового ключа.
- **Входы:** `Signal: In`, `Data: Key (String / Int)`.
- **Выходы:** `Signal: Case 1..N`, `Signal: Default`.
- **Свойства:** Динамический список пар «Значение ключа → Имя выходного порта».
- **Пример:** В зависимости от статуса проекта («Идея», «В разработке», «Релиз», «Архив») импульс направляет фокус на соответствующий этаж или зону.

#### 1.3. `Flow_Debounce` (Подавитель дребезга сигналов)
- **Назначение:** Пропускает только первый сигнал в серии, игнорируя последующие в течение заданного окна времени.
- **Входы:** `Signal: In`, `Data: WindowMs (Int)`.
- **Выходы:** `Signal: Out`.
- **Свойства:** Время отсечки (по умолчанию 500 мс).
- **Пример:** Предотвращает множественный запуск тяжелого скрипта при быстром клике по чекбоксу.

#### 1.4. `Flow_Throttle` (Регулятор частоты импульсов)
- **Назначение:** Пропускает сигналы не чаще одного раза за заданный интервал, аккумулируя последний.
- **Входы:** `Signal: In`, `Data: PeriodMs (Int)`.
- **Выходы:** `Signal: Out`.
- **Свойства:** Стратегия: `Leading edge` (первый сразу) или `Trailing edge` (последний в конце окна).
- **Пример:** Плавное обновление прогресс-бара маяка при потоковом добавлении задач.

#### 1.5. `Flow_FlipFlop` (Бистабильный триггер-тумблер)
- **Назначение:** При каждом входящем импульсе переключает свое состояние между двумя альтернативными выходами A и B.
- **Входы:** `Signal: Toggle`, `Signal: Reset`.
- **Выходы:** `Signal: OutA`, `Signal: OutB`, `Data: State (Bool)`.
- **Свойства:** Начальное состояние (`A` или `B`).
- **Пример:** Одна кнопка или хоткей попеременно скрывает и показывает вспомогательные фото-референсы на холсте.

#### 1.6. `Flow_Latch` (Защелка состояния / RS-триггер)
- **Назначение:** Блокирует прохождение сигналов до тех пор, пока на порт Reset не поступит разрешающий импульс.
- **Входы:** `Signal: Set`, `Signal: Reset`, `Signal: In`.
- **Выходы:** `Signal: Out (если открыто)`, `Data: IsOpen (Bool)`.
- **Свойства:** Начальное состояние (закрыто/открыто).
- **Пример:** Блокирует повторное срабатывание вечерней ретроспективы, если она уже была пройдена сегодня.

#### 1.7. `Flow_CounterGate` (Счетчик-дозатор импульсов)
- **Назначение:** Пропускает импульс на выход только после того, как на вход пришло ровно N импульсов.
- **Входы:** `Signal: In`, `Signal: Reset`, `Data: TargetCount (Int)`.
- **Выходы:** `Signal: OnReached`, `Data: CurrentCount (Int)`.
- **Свойства:** Порог срабатывания `TargetCount`, чекбокс автоматического сброса при достижении порога.
- **Пример:** После выполнения 4 спринтов Pomodoro активирует сигнал на длинный перерыв.

#### 1.8. `Flow_RandomRouter` (Вероятностный разветвитель)
- **Назначение:** Направляет импульс в один из случайных выходов с заданными весами вероятности.
- **Входы:** `Signal: In`.
- **Выходы:** `Signal: Out 1`, `Signal: Out 2`, `Signal: Out 3`.
- **Свойства:** Процентные веса для каждого выхода (например, 50% / 30% / 20%).
- **Пример:** Выбор случайного формата разминки или случайной темы для вечернего фрирайтинга.

#### 1.9. `Flow_Sequence` (Последовательный каскадер с задержками)
- **Назначение:** При одном входящем импульсе поочередно активирует цепочку выходов 1..N с фиксированными паузами.
- **Входы:** `Signal: Start`, `Signal: Abort`.
- **Выходы:** `Signal: Step 1..N`, `Signal: OnComplete`.
- **Свойства:** Список шагов и задержки в миллисекундах между ними.
- **Пример:** Сценарий «Подготовка к рабочему дню»: шаг 1 — открыть дашборд, через 2 сек — подсветить задачи дня, через 5 сек — запустить плейлист.

#### 1.10. `Flow_Filter` (Фильтр полезной нагрузки)
- **Назначение:** Пропускает импульс дальше только в том случае, если контекстный payload удовлетворяет условию (RegEx, длина текста, тег).
- **Входы:** `Signal: In`, `Data: Payload (Any)`.
- **Выходы:** `Signal: Accepted`, `Signal: Rejected`.
- **Свойства:** Правило фильтрации (например, `Payload contains '#urgent'`).
- **Пример:** Из потока входящих быстрых заметок отфильтровывает только те, которые помечены тегом `#bug`.

### Семейство 2: Time & Scheduling (Время, таймеры, периодичность)

#### 2.1. `Time_CronSchedule` (Планировщик по календарной маске)
- **Назначение:** Вырабатывает импульс по стандартному cron-расписанию операционной системы.
- **Входы:** `Signal: Enable`, `Signal: Disable`.
- **Выходы:** `Signal: Trigger`.
- **Свойства:** Строка Cron (например, `0 9 * * 1-5` — 9:00 по будням), выбор часового пояса.
- **Пример:** Ежеутренний запуск сборщика задач на день.

#### 2.2. `Time_RelativeDelay` (Прецизионная линия задержки)
- **Назначение:** Задерживает входящий импульс на строго фиксированное время (секунды / минуты / часы).
- **Входы:** `Signal: In`, `Signal: Cancel`, `Data: DelaySeconds (Int)`.
- **Выходы:** `Signal: Out`, `Data: RemainingSec (Int)`.
- **Свойства:** Единицы измерения времени, режим отмены при повторном входящем сигнале.
- **Пример:** «Напомнить через 45 минут после включения задачи».

#### 2.3. `Time_CountdownDeadline` (Интерактивный дедлайн с отсчетом)
- **Назначение:** Привязывается к жесткой дате и времени, непрерывно транслируя процент оставшегося времени и триггеря алерты.
- **Входы:** `Data: TargetDateTime (Timestamp)`.
- **Выходы:** `Signal: OnExpired`, `Signal: OnWarning50%`, `Signal: OnWarning10%`, `Data: Progress (0.0..1.0)`.
- **Свойства:** Дата и время дедлайна, выбор звукового профиля тревоги.
- **Пример:** Дедлайн подачи заявки на грант: меняет цвет ноды задачи с зеленого на желтый за 3 дня и на красный за 2 часа.

#### 2.4. `Time_PomodoroTimer` (Двухфазный таймер фокуса)
- **Назначение:** Полноценный конечный автомат техники Pomodoro (Focus / Short Break / Long Break).
- **Входы:** `Signal: Start`, `Signal: Pause`, `Signal: Skip`.
- **Выходы:** `Signal: OnWorkStart`, `Signal: OnBreakStart`, `Signal: OnCycleEnd`, `Data: PhaseName (String)`.
- **Свойства:** Длительность работы (25 мин), малого перерыва (5 мин), большого перерыва (15 мин), циклов до длинного (4).
- **Пример:** Автоматически переводит рабочее пространство на этаж отдыха по окончании 25-минутного спринта.

#### 2.5. `Time_FloatingInterval` (Плавающий циклический интервал)
- **Назначение:** Запускает отсчет следующего интервала не по жесткой сетке, а только ПОСЛЕ подтверждения выполнения предыдущего действия.
- **Входы:** `Signal: TaskDoneAck`, `Data: IntervalHours (Int)`.
- **Выходы:** `Signal: NextDue`.
- **Свойства:** Интервал (например, 72 часа).
- **Пример:** Интервальное повторение учебных заметок или полив цветов: следующий полив через 3 дня после реального полива, а не строго по понедельникам.

#### 2.6. `Time_WindowCondition` (Валидатор временных окон)
- **Назначение:** Проверяет, попадает ли текущее время в разрешенный интервал (например, «Рабочее время с 10:00 до 19:00»).
- **Входы:** `Signal: CheckNow`.
- **Выходы:** `Signal: InsideWindow`, `Signal: OutsideWindow`, `Data: IsInside (Bool)`.
- **Свойства:** Начало окна, конец окна, разрешенные дни недели.
- **Пример:** Запрещает отправку звуковых уведомлений и всплывающих окон, если на часах ночь.

#### 2.7. `Time_Stopwatch` (Секундомер активности)
- **Назначение:** Замеряет чистое затраченное время между сигналами Start и Stop, накапливая общее время сессии.
- **Входы:** `Signal: Start`, `Signal: Stop`, `Signal: Reset`.
- **Выходы:** `Data: ElapsedSeconds (Int)`, `Data: FormattedTime (String)`.
- **Свойства:** Автоматическое сохранение накопленного времени в атрибут привязанной задачи.
- **Пример:** Трекинг реального времени, потраченного на написание кода в проекте.

#### 2.8. `Time_SolarClock` (Астрономический триггер рассвета/заката)
- **Назначение:** Генерирует события при наступлении естественных фаз дня по географическим координатам пользователя.
- **Входы:** `Data: Lat/Lon (optional)`.
- **Выходы:** `Signal: OnDawn`, `Signal: OnNoon`, `Signal: OnDusk`, `Signal: OnMidnight`.
- **Свойства:** Выбор часового пояса и города или автоопределение Windows.
- **Пример:** Переключение темы холста и фоновой подсветки ядра «ME» с дневного режима на ночной эмбиент.

#### 2.9. `Time_DriftCompensator` (Защищенный таймер сна системы)
- **Назначение:** Корректно обрабатывает ситуации, когда компьютер уходил в спящий режим / гибернацию.
- **Входы:** `Signal: Sync`.
- **Выходы:** `Signal: OnAwakeWithMissedEvents`, `Data: MissedSeconds (Int)`.
- **Свойства:** Политика компенсации: проигнорировать пропущенное или сгенерировать единичный суммарный отчет.
- **Пример:** При открытии ноутбука утром сообщает: «Пока вы спали, истекло 3 дедлайна».

### Семейство 3: Task & State Machine (Задачи, стейт-машины, прогресс)

#### 3.1. `Task_LifecycleController` (Полный контроллер жизненного цикла)
- **Назначение:** Управляет формальным статусом задачи в виде конечного автомата.
- **Входы:** `Signal: SetTodo`, `Signal: SetInProgress`, `Signal: SetDone`, `Signal: SetCancelled`.
- **Выходы:** `Signal: OnStateChanged`, `Data: CurrentState (Enum)`.
- **Свойства:** Начальное состояние, список блокирующих условий.
- **Пример:** Переводит задачу в статус «Ready to Test» только после того, как все зависимые задачи получили статус «Done».

#### 3.2. `Task_DependencyAggregator` (Агрегатор предварительных требований)
- **Назначение:** Проверяет готовность N входящих задач-предшественников.
- **Входы:** `Data: TasksIn (List<TaskRef>)`.
- **Выходы:** `Signal: AllCompleted`, `Data: CompletedCount (Int)`, `Data: TotalCount (Int)`, `Data: ProgressRatio (Float)`.
- **Свойства:** Режим: «Требуются абсолютно все» или «Достаточно K из N».
- **Пример:** Разблокирует ноду «Публикация статьи» только когда готовы задачи «Вычитка», «Иллюстрации» и «Вёрстка».

#### 3.3. `Task_ChecklistProgress` (Диспетчер чеклистов)
- **Назначение:** Мониторит элементы чеклиста `[ ]` внутри текста markdown-ноды.
- **Входы:** `Signal: Rescan`, `Data: NoteRef`.
- **Выходы:** `Signal: OnAllChecked`, `Signal: OnAnyChecked`, `Data: CheckedCount (Int)`, `Data: UncheckedCount (Int)`.
- **Свойства:** Селектор тегов или заголовков внутри заметки.
- **Пример:** Показывает мини-прогрессбар прямо над заголовком ноды на холсте.

#### 3.4. `Task_PriorityEscalator` (Автоматический эскалатор приоритета)
- **Назначение:** Повышает уровень важности (Basic → Medium → Important → Immediately) по мере приближения к дедлайну или при отсутствии прогресса.
- **Входы:** `Signal: Tick`, `Data: TaskRef`.
- **Выходы:** `Signal: OnEscalated`, `Data: CurrentPriority (Enum)`.
- **Свойства:** Временная шкала эскалации (например, за 24 ч до дедлайна — сразу Important).
- **Пример:** Задача тихо висела неделю: за 12 часов до дедлайна нода вспыхивает фиолетовым свечением (`Immediately`) и перемещается на передний план.

#### 3.5. `Task_EffortEstimator` (Сумматор трудозатрат и story points)
- **Назначение:** Складывает оценки сложности (часы, баллы, сложность) по всему поддереву задач маяка.
- **Входы:** `Data: BeaconSubtreeRef`.
- **Выходы:** `Data: TotalHours (Float)`, `Data: RemainingHours (Float)`.
- **Свойства:** Формат оценки (`1h 30m`, `SP: 5`).
- **Пример:** Подсчет суммарного веса спринта в зоне «Разработка ядра».

#### 3.6. `Task_RecurringSpawner` (Репликатор периодических задач)
- **Назначение:** При закрытии регулярной задачи клонирует шаблон ноды и создает свежую копию на следующую дату.
- **Входы:** `Signal: TaskCompleted`, `Data: TemplateTaskRef`.
- **Выходы:** `Signal: OnSpawned`, `Data: NewTaskRef`.
- **Свойства:** Правило сдвига дедлайна (`+1 неделя`), сохранение связей с маяком.
- **Пример:** Еженедельный бэкап: старая нода архивируется, свежая встает на ее место с датой следующего воскресенья.

#### 3.7. `Task_BurnDownTracker` (Вычислитель диаграммы сгорания задач)
- **Назначение:** Замеряет скорость закрытия задач во времени для зоны или этажа.
- **Входы:** `Signal: SampleTick`, `Data: ZoneRef`.
- **Выходы:** `Data: VelocityPerDay (Float)`, `Data: ProjectedCompletionDate (Date)`.
- **Свойства:** Длина окна замера (например, последние 14 дней).
- **Пример:** Прогнозирует реальную дату завершения проекта на основе текущей продуктивности.

#### 3.8. `Task_ArchiveSweeper` (Уборщик выполненных задач)
- **Назначение:** Автоматически собирает выполненные задачи, возраст которых превышает N дней, и переносит их на этаж архива.
- **Входы:** `Signal: RunCleanup`, `Data: SourceFloorRef`, `Data: TargetArchiveFloorRef`.
- **Выходы:** `Signal: OnCleaned`, `Data: MovedCount (Int)`.
- **Свойства:** Задержка архивации (например, 7 дней после завершения).
- **Пример:** Очищает активную рабочую зону от визуального шума старых закрытых тикетов.

#### 3.9. `Task_ContextSwitchCost` (Анализатор распыления внимания)
- **Назначение:** Фиксирует частоту переключения между разнородными задачами за день и предупреждает о перегрузке.
- **Входы:** `Signal: ActiveTaskChanged`.
- **Выходы:** `Signal: WarningHighSwitching`, `Data: SwitchesCount (Int)`.
- **Свойства:** Порог предупреждения (например, более 8 смен контекста в час).
- **Пример:** Если пользователь метается между 10 задачами на разных этажах, выдает предупреждение: «Сфокусируйтесь на одной задаче».

### Семейство 4: Spatial, Floors & Canvas (Камера, этажи, маяки, зоны, слои)

#### 4.1. `Spatial_CameraFocus` (Плавный режиссер камеры)
- **Назначение:** Плавно перемещает фокус камеры на заданный объект с кинематографической интерполяцией (Ease-in-out).
- **Входы:** `Signal: Focus`, `Data: TargetObjectRef`, `Data: ZoomLevel (Float)`.
- **Выходы:** `Signal: OnArrived`.
- **Свойства:** Длительность полета камеры (по умолчанию 600 мс), кривая анимации.
- **Пример:** При срабатывании будильника камера плавно подлетает прямо к ноде срочного чек-листа.

#### 4.2. `Spatial_FloorPortal` (Двусторонний межэтажный портал)
- **Назначение:** Парная нода-шлюз, связывающая вход на этаже A с выходом на этаже B без захламления нулевого этажа.
- **Входы:** `Signal: In`, `Data: Payload (Any)`.
- **Выходы:** `Signal: Out (на целевом этаже)`, `Data: PayloadOut`.
- **Свойства:** Привязка к парному порталу, опция «Переключить активный этаж пользователя при клике».
- **Пример:** Клик по порталу на 1 этаже («Архитектура») мгновенно телепортирует пользователя на 4 этаж («API спецификации»).

#### 4.3. `Spatial_BeaconLevelIsolator` (Изолятор внимания поддерева маяка)
- **Назначение:** Программно активирует режим `Ctrl+G`: уводит весь остальной холст в 50% прозрачность, выделяя только выбранный маяк.
- **Входы:** `Signal: Isolate`, `Signal: RestoreNormal`, `Data: BeaconRef`.
- **Выходы:** `Signal: OnStateApplied`.
- **Свойства:** Степень затемнения фона (от 10% до 90%).
- **Пример:** При старте спринта изолирует только ветку «Текущий спринт», скрывая гигантскую карту идей вокруг.

#### 4.4. `Spatial_ZoneColorSync` (Динамический стилизатор зоны)
- **Назначение:** Меняет цвет заливки и границы зоны в зависимости от общего состояния дел внутри нее.
- **Входы:** `Signal: Update`, `Data: ZoneRef`, `Data: StatusColor (ColorHex)`.
- **Выходы:** `Signal: OnColorChanged`.
- **Свойства:** Палитра состояний (Все задачи закрыты → Зеленый, Есть блокеры → Красный).
- **Пример:** Зона «Подготовка релиза» автоматически становится ярко-зеленой, когда закрыт последний чекбокс.

#### 4.5. `Spatial_MinimapPin` (Метка глобального радара)
- **Назначение:** Отображает важный маркер на мини-карте/навигаторе, даже когда камера максимально приближена к другой части холста.
- **Входы:** `Signal: PulsePin`, `Data: Label (String)`.
- **Выходы:** `Signal: OnClickedFromRadar`.
- **Свойства:** Иконка пина, цвет пульсации.
- **Пример:** Пульсирующая красная точка на краю экрана указывает направление к горящему дедлайну.

#### 4.6. `Spatial_ProximityTrigger` (Датчик близости курсора / камеры)
- **Назначение:** Срабатывает, когда курсор пользователя или фокус камеры приближается к координатам ноды ближе определенного радиуса.
- **Входы:** `Data: RadiusPixels (Int)`.
- **Выходы:** `Signal: OnEnter`, `Signal: OnLeave`, `Data: Distance (Float)`.
- **Свойства:** Радиус чувствительности (например, 300px).
- **Пример:** Автоматически разворачивает подробный справочный блок при наведении камеры на компактную карточку модуля.

#### 4.7. `Spatial_SmartLayoutPacker` (Организатор пространства зоны)
- **Назначение:** Автоматически выравнивает ноды внутри полигональной зоны сеткой или деревом без ручного перетаскивания.
- **Входы:** `Signal: Realign`, `Data: ZoneRef`.
- **Выходы:** `Signal: OnAligned`.
- **Свойства:** Алгоритм укладки (`Grid`, `Hierarchical Tree`, `Radial`), отступы между нодами.
- **Пример:** По нажатию хоткея наводит порядок в зоне заметок, аккуратно расставляя их с зазором 24px.

#### 4.9. `Spatial_ZonePolygonClipper` (Программный редактор формы зоны)

### Семейство 7: Math, Variables & Data Manipulation (Переменные, счетчики, формулы, агрегаты)

#### 7.1. `Data_GlobalVariable` (Глобальная переменная состояния проекта)
- **Назначение:** Хранит именованное значение (`String`, `Number`, `Bool`, `JSON`), доступное из любой точки холста и сохраняемое на диске.
- **Входы:** `Signal: Set`, `Data: NewValue (Any)`.
- **Выходы:** `Signal: OnChanged`, `Data: Value (Any)`.
- **Свойства:** Имя переменной, тип данных, значение по умолчанию.
- **Пример:** Флаг `CurrentSprintNumber = 4` доступен всем генераторам задач и отчетов.

#### 7.2. `Data_MathExpression` (Математический вычислитель формул)
- **Назначение:** Вычисляет произвольное алгебраическое выражение от нескольких числовых входов.
- **Входы:** `Data: a (Float)`, `Data: b (Float)`, `Data: c (Float)`.
- **Выходы:** `Data: Result (Float)`.
- **Свойства:** Текст формулы (например, `(a * 0.7) + (b * 0.3) / max(c, 1)`).
- **Пример:** Расчет индекса продуктивности дня по формуле, учитывающей закрытые задачи и часы фокуса.

#### 7.3. `Data_AccumulatorSum` (Суммирующий аккумулятор)
- **Назначение:** При каждом импульсе прибавляет входящую дельту к накопленному итоговому значению.
- **Входы:** `Signal: Add`, `Signal: Reset`, `Data: Delta (Float)`.
- **Выходы:** `Data: Total (Float)`.
- **Свойства:** Начальное значение, верхний и нижний пределы (Clamping).
- **Пример:** Подсчет выпитых стаканов воды или пройденных шагов за день.

#### 7.4. `Data_ThresholdComparator` (Пороговый компаратор с гистерезисом)
- **Назначение:** Сравнивает входящее число с порогом, исключая частое мерцание на границе за счет полосы нечувствительности.
- **Входы:** `Data: Value (Float)`, `Data: Threshold (Float)`.
- **Выходы:** `Signal: OnAbove`, `Signal: OnBelow`, `Data: IsAbove (Bool)`.
- **Свойства:** Дельта гистерезиса (например, порог 100, гистерезис 5).
- **Пример:** Контроль баланса бюджета проекта: предупреждение при остатке менее $500.

#### 7.5. `Data_ListAggregator` (Агрегатор коллекций и списков)
- **Назначение:** Вычисляет статистики по массиву чисел (Sum, Average, Min, Max, Median).
- **Входы:** `Data: Items (List<Float>)`.
- **Выходы:** `Data: Sum (Float)`, `Data: Avg (Float)`, `Data: Min (Float)`, `Data: Max (Float)`.
- **Свойства:** Операция по умолчанию.
- **Пример:** Средняя оценка фокуса за неделю по результатам опросов после Pomodoro.

#### 7.6. `Data_RangeMapper` (Нормализатор диапазонов / Lerp)
- **Назначение:** Линейно переводит число из диапазона `[InMin..InMax]` в диапазон `[OutMin..OutMax]`.
- **Входы:** `Data: Value (Float)`.
- **Выходы:** `Data: MappedValue (Float)`.
- **Свойства:** Входной диапазон (0..100), выходной диапазон (0.0..1.0) или (HEX светлый..HEX темный).
- **Пример:** Перевод процента выполненных задач (0..100) в прозрачность фонового слоя зоны.

#### 7.7. `Data_JSONParserQuery` (Парсер структурированных данных)
- **Назначение:** Извлекает вложенные поля из JSON-строки или словаря по пути (JSONPath / Dot-notation).
- **Входы:** `Data: JsonString (String)`.
- **Выходы:** `Data: ExtractedValue (Any)`.
- **Свойства:** Путь к ключу (например, `$.user.stats.completed_tasks`).
- **Пример:** Интеграция с локальными логами сторонних утилит.

#### 7.8. `Data_RollingAverageWindow` (Скользящее среднее во времени)
- **Назначение:** Удерживает буфер из последних N замеров и отдает сглаженное значение без резких выбросов.
- **Входы:** `Signal: Sample`, `Data: NewVal (Float)`.
- **Выходы:** `Data: SmoothAvg (Float)`.
- **Свойства:** Размер скользящего окна (например, последние 7 дней).
- **Пример:** Сглаженный тренд продуктивности за неделю.

#### 7.9. `Data_BooleanLatchArray` (Битовая маска флагов)
- **Назначение:** Хранит вектор из 8 или 16 независимых булевых флагов в одном компактном состоянии.
- **Входы:** `Signal: SetBit(Index)`, `Signal: ClearBit(Index)`.
- **Выходы:** `Data: MaskInt (Int)`, `Data: AllBitsSet (Bool)`.
- **Свойства:** Подписи к каждому биту.
- **Пример:** Чеклист ежедневных привычек (Зарядка, Чтение, Код, Медитация, Прогулка): когда все биты равны 1, выдается победный салют на холсте.

#### 9.2. `System_GlobalHotkeyListener` (Перехватчик глобальных хоткеев)
- **Назначение:** Регистрирует общесистемную комбинацию клавиш Windows (даже когда окно Mastermind свернуто).
- **Входы:** `Data: KeyChord (e.g. 'Ctrl+Shift+Space')`.
- **Выходы:** `Signal: OnHotkeyPressed`.
- **Свойства:** Режим перехвата: активен всегда или только при фокусе приложения.

#### 9.3. `System_WindowsNotifier` (Диспетчер нативных тостов Windows)
- **Назначение:** Отправляет системное всплывающее уведомление Windows 10/11 в Action Center с кнопками действий.

- **Выходы:** `Signal: OnClicked`, `Signal: OnActionButton1`, `Signal: OnDismissed`.
- **Свойства:** Звуковой профиль оповещения Windows, логотип приложения.
- **Пример:** Уведомление о дедлайне всплывает в углу экрана Windows с кнопкой «Открыть в Mastermind».

#### 9.4. `System_UserIdleDetector` (Датчик простоя пользователя)
- **Назначение:** Определяет отсутствие ввода с мыши и клавиатуры в ОС дольше N минут.

- **Выходы:** `Signal: OnUserBecameIdle`, `Signal: OnUserReturned`, `Data: IdleDurationSec (Int)`.
- **Свойства:** Время отсечки (по умолчанию 5 минут).

#### 9.5. `System_AudioTonePlayer` (Синтезатор звуковых сигналов)
- **Назначение:** Воспроизводит процедурные звуковые тоны (частота, синусоида, клик, аккорд) без внешних файлов.
- **Входы:** `Signal: PlayTone`, `Data: FrequencyHz (Int)`, `Data: DurationMs (Int)`.
- **Выходы:** `Signal: OnToneFinished`.
- **Свойства:** Пресеты звуков (Колокольчик, Успех, Ошибка, Клик тумблера).

#### 9.6. `System_LocalFileWatch` (Наблюдатель за локальными файлами)
- **Назначение:** Отслеживает изменения текстового или кодового файла на диске Windows (`.rs`, `.md`, `.json`).
- **Входы:** `Data: FilePath (String)`.
- **Выходы:** `Signal: OnFileModified`, `Data: FileContent (String)`.
- **Свойства:** Дебаунс файловых событий (300 мс).
- **Пример:** Автоматическое обновление ноды со сниппетом кода при его сохранении в IDE.

#### 9.7. `System_BatteryAndPowerState` (Монитор электропитания)
- **Назначение:** Отслеживает уровень заряда батареи ноутбука и переход на питание от аккумулятора.
- **Входы:** `Signal: Query`.
- **Выходы:** `Signal: OnLowBattery`, `Data: BatteryPercent (Int)`, `Data: IsPluggedIn (Bool)`.
- **Свойства:** Порог низкого заряда (20%).

#### 9.8. `System_ProcessFocusDetector` (Детектор активного приложения)
- **Назначение:** Фиксирует имя текущего активного процесса в Windows (например, `code.exe`, `blender.exe`, `chrome.exe`).

- **Свойства:** Черный список отвлекающих приложений.
- **Пример:** Если открыт `steam.exe` во время рабочего спринта, нода может выдать деликатное напоминание о фокусе.

- **Свойства:** Список сохраняемых атрибутов.

#### 10.7. `Meta_GraphSafetyFuse` (Предохранитель от перегрузок рантайма)
- **Назначение:** Автоматически размыкает цепь исполнения, если частота импульсов превышает безопасный предел (защита от багов пользователя).

## 6. Рабочая гипотеза об Уроборосе: циклы, рестарты и ветвления

В строке 14 файла `hive.md` оставлена загадочная, но критически важная запись:
> `"заметка на будущее если не забуду" - парадокс уробороса РЕШИТЬ!`

### 6.1. Может ли парадокс Уробороса означать проблему циклов?

Пользователь пока не определил, что означает эта заметка в контексте Mastermind. Ниже проверяется одна возможная трактовка: **самореферентные циклические зависимости** в гибридном редакторе заметок и автоматизации.

1. **Исполнительный цикл (Execution Infinite Loop):**  
   Нода А по событию дергает Ноду Б → Нода Б дергает Ноду В → Нода В дергает Ноду А. Если в этой цепи нет квантованного ожидания времени или реакции человека, весь интерфейс Tauri/Rust входит в бесконечный синхронный шторм событий, утилизирует 100% CPU и намертво зависает.
2. **Парадокс состояния (State Feedback Oscillation):**  
   Условие `IF` проверяет: «Если задача не выполнена, пометить ее выполненной». Как только она становится выполненной, условие перестает выполняться и снимает флаг. Возникает высокочастотный дребезг состояния (High-frequency state oscillation).
3. **Онтологический цикл (Knowledge Self-Reference):**  
   Заметка «Что такое сознание?» ссылается на «Мышление», «Мышление» ссылается на «Мозг», «Мозг» ссылается на «Сознание». В Obsidian это естественное состояние фрактальной мысли, но для наивного графового алгоритма обхода (например, подсчет всех связанных слов маяка `Ctrl+F` из `hive.md`) это приводит к переполнению стека (`StackOverflowError`).

```
                ┌──────────────────────────────────────────────────┐
                │          ПАРАДОКС УРОБОРОСА В MASTERMIND         │
                └─────────────────────────┬────────────────────────┘
                                          │
                  ┌───────────────────────┴───────────────────────┐
                  ▼                                               ▼
     ┌─────────────────────────┐                     ┌─────────────────────────┐
     │   ОНТОЛОГИЧЕСКИЙ ЦИКЛ   │                     │   ИСПОЛНИТЕЛЬНЫЙ ЦИКЛ   │
     │   (Граф связей знаний)  │                     │   (Шина событий Time/IF)│
     ├─────────────────────────┤                     ├─────────────────────────┤
     │ • Заметка А <-> Б <-> А │                     │ • Акт А -> Акт Б -> А   │
     │ • ЗАКОНЕН И ЖЕЛАТЕЛЕН   │                     │ • СМЕРТЕЛЕН БЕЗ ЗАЩИТЫ  │
     │ • Решение: Посещенные   │                     │ • Решение: Лимит тиков  │
     │   ноды (HashSet<UUID>)  │                     │   + Обязательный Latch/ │
     │   при рекурсивном обходе│                     │   Delay в каждой петле  │
     └─────────────────────────┘                     └─────────────────────────┘
```

### 6.2. Возможные защитные правила, если гипотеза о циклах верна

1. **Аксиома разделения графов:**  
   Связи знаний (`Knowledge Edges`, линии `C` и `V`) **никогда** не транслируют импульсы исполнения. Обход графа знаний для подсчета статистики использует стандартный `HashSet<UUID>` посещенных нод, мгновенно обрывая циклические ссылки.
2. **Предложение: бюджет выполнения (Execution Step Budget):**  
   Можно рассмотреть счетчик жизни каскадного импульса; `TTL = 128` здесь только пример для обсуждения. Значение лимита, единица измерения и поведение при превышении должны быть определены ответами пользователя.
3. **Предложение: задержка или ограничитель цикла (Delay / Latch Principle):**  
   Один из вариантов — считать замкнутый исполнительный контур допустимым при наличии асинхронной задержки или явного ограничителя. Это не обязательное требование пользователя; альтернативами могут быть предупреждение, счетчик итераций, ручное разрешение цикла или запрет конкретного запуска:
   - `Time_RelativeDelay` (пауза минимум на 1 тик рантайма).
   - `Time_CronSchedule` или `Time_FloatingInterval`.
   - `Human_ConfirmDecline` (ожидание действия человека).
   - `Flow_Latch` / `Flow_CounterGate`.
4. **Квантование по тикам рантайма (Tick-based Event Queue):**  
   Сигналы не вызываются мгновенными синхронными вызовами функций Rust, а помещаются в очередь событий `EventQueue`. Очередь обрабатывается дискретными порциями с частотой 60 Гц, гарантируя, что UI-поток Tauri никогда не заблокируется.

### 6.3. 10 сценариев циклов, рестартов и ветвлений с разбором поведения

#### Сценарий 1: Честный цикл Pomodoro (Легитимный повторяющийся цикл)
- **Цепочка:** `Time_PomodoroTimer` (Work 25m) → `Human_AudioNudge` → `Human_ConfirmDecline` («Готов отдыхать?») → `Time_PomodoroTimer` (Break 5m) → Возврат на Work.
- **Поведение системы:** Цикл легален, так как на каждом шаге присутствует физическое ожидание времени (25 мин, 5 мин) и подтверждение пользователя. Уроборос укрощен.

#### Сценарий 2: Мертвая петля мгновенного авто-рестарта (Deadly Zero-Delay Loop)
- **Цепочка:** Нода `IF` проверяет `Counter < 100`. Если True → инкремент `Counter` → немедленный триггер `IF`.
- **Возможное поведение:** без демпфера каскад может быстро исчерпать предложенный бюджет; пример `TTL = 128` не фиксирует значение. Отключение провода и красная подсветка петли также остаются вариантами для выбора.

#### Сценарий 3: Маятник двух задач (Mutual Task Deadlock)
- **Цепочка:** Задача 1 зависит от завершения Задачи 2. Задача 2 зависит от завершения Задачи 1.
- **Поведение системы:** Анализатор зависимостей `Task_DependencyAggregator` запускает топологическую сортировку (алгоритм Кана). При обнаружении цикла обе задачи подсвечиваются статусом `[CYCLE ERROR: Deadlock]`, а в панели маяка появляется предупреждение о невозможности старта.

#### Сценарий 4: Дневной цикл привычек с ночным сбросом (Daily Habit Reset)
- **Цепочка:** Утром активируются 5 задач привычек → В течение дня пользователь отмечает их `Done` → В 00:00 нода `Time_CronSchedule` вырабатывает импульс `Reset` → Чекбоксы сбрасываются в `Todo`, счетчик дней увеличивается на 1.
- **Поведение системы:** Классический 24-часовой рестарт. Система детерминированно сохраняет историю вчерашнего дня в лог и обновляет текущее состояние холста.

#### Сценарий 5: Каскадный откат по ветвлению (Branch Fallback with Retry)
- **Цепочка:** Узел действия пытается выполнить системную команду. Ветка `OnSuccess` ведет вперед к завершению проекта. Ветка `OnFailure` ведет к узлу `Time_RelativeDelay` (5 мин) и возвращает импульс на вход повторной попытки (Retry), но не более 3 раз через `Flow_CounterGate`.
- **Поведение системы:** Устойчивый шаблон автоматизации с экспоненциальной задержкой и гарантированным выходом из цикла при исчерпании лимита попыток.

#### Сценарий 6: Эскалация «Не отстану, пока не ответишь» (Nagging Loop)
- **Цепочка:** Срабатывает будильник → Запрос подтверждения у пользователя → Пользователь игнорирует или нажимает «Remind in 5m» → Сигнал идет в таймер задержки 5 минут → Возврат на будильник.
- **Поведение системы:** Безопасный полуавтоматический цикл. Задержка 5 минут гарантирует отсутствие зависаний.

#### Сценарий 7: Автоматическая генерация подзадач до выполнения условия (Generative Unrolling)
- **Цепочка:** Задача «Изучить 10 глав» → Цикл: `Meta_DynamicNodeSpawner` создает карточку главы K → `Counter = K + 1` → Проверка `Counter <= 10` → Если True, переход на следующий шаг цикла через микропаузу (16 мс).
- **Поведение системы:** Карточки красиво раскладываются на этаже одна за другой с плавной анимацией появления.

#### Сценарий 8: Пинг-понг между двумя этажами (Cross-Floor Teleport Ping-Pong)
- **Цепочка:** Нода на Этаже 1 триггерит телепорт на Этаж 2. Нода на Этаже 2 по событию входа камеры триггерит телепорт обратно на Этаж 1.
- **Поведение системы:** Без защиты камера металась бы между этажами 60 раз в секунду, вызывая эпилептический припадок. Система фиксирует `Camera Thrashing`: повторный запрос телепорта блокируется на 1.5 секунды, пользователю выдается тост: «Заблокирован циклический прыжок камеры».

#### Сценарий 9: Обратная связь с подавлением (Negative Feedback Loop / Балансир)
- **Цепочка:** Если число активных задач в зоне > 5, блокируется создание новых задач. Как только число падает до 3, шлюз разблокируется.
- **Поведение системы:** Классический триггер Шмитта с гистерезисом. Устраняет метания системы на границе ровно в 5 задач.

#### Сценарий 10: Рекурсивный обход майнд-карты (Mind Map Graph Traversal)
- **Цепочка:** Пользователь нажимает кнопку «Посчитать общее число слов проекта» на ядре «ME». Импульс рекурсивно ветвится по всем исходящим линиям `C`.
- **Поведение системы:** Алгоритм DFS/BFS использует временный битовый массив посещенных узлов `VisitedNodes`. Любая повторная встреча с уже пройденной нодой мгновенно игнорируется. Результат возвращается без зацикливания.
