# MCP token diet (вариант B) — дизайн

Дата: 2026-11-27. Выбран пользователем: вариант B (A + короткие id).

## Зачем

Агент, работающий с hive через MCP, тратит десятки тысяч символов на рядовые вызовы: на
sidequest-kingdom-files (528 нод, 31 зона, 448 связей) один `list_zones` — ~70,8k символов,
`list_nodes` (100 нод) — ~74,7k. Пользователь хочет, чтобы от одного движения ноды и одного
запроса списка не «летело» 50k+ символов. Успех — те же задачи агент делает в разы дешевле, ничего не
теряя в точности.

## Откуда объём (замерено)

1. Каждый ответ отдаётся дважды: `content[0].text` = pretty JSON и `structuredContent` = та же
   структура (`mcp_stdio/tools.rs` → `ok()`). Pretty-отступы ещё ~+50% к компактному.
2. `zones.list` отдаёт полный список id нод-членов и все точки полигона: UUID — 20k из 28k
   компактного ответа.
3. UUID по 36 символов везде (id, from, to, zoneId, ids…).
4. Координаты с 17 знаками после запятой; поля `null`/`[]` в каждом объекте.
5. Ответы записи повторяют полную карточку: `move_nodes` возвращает summary каждой ноды с
   превью текста.

## Цели

- Ответ каждого инструмента отдаётся один раз, компактно.
- Короткие id во всех ответах; инструменты принимают и короткие, и полные.
- Ответы `list_zones`, `list_nodes`, записи — без лишнего: только то, что агенту нужно для следующего шага.
- Ориентиры на sidequest-kingdom-files: `list_zones` ≤ 4k символов (было 70,8k), `list_nodes` по
  умолчанию ≤ 10k (было 74,7k), `move_nodes` ≤ 50 символов.

## Не цели

- **Формат файлов проекта не меняем.** Проверка истории brother eye и sidequest-kingdom-files
  показала: шум от точек крепления плавных линий убран ещё в 2.0.3 (ff488ff), а коммит с 78 файлами
  связей (27f75f5, 20.10) — разовая чистка при переходе на 2.0.3. Сейчас сдвиг ноды меняет один файл,
  две строки. Убрать `null`/`[]` и округлить координаты в файлах можно, но пока у соавторов
  (Chakar3285, nikenmar) стоит версия старее, их hive при полном сохранении вернёт поля обратно
  во все файлы — массовые диффы туда-обратно. Выигрыш косметический (файлы меньше, файлов столько же).
  Отложено до момента, когда все на новой версии, и то по отдельному решению.
- Старый Node-сервер (`C:\mcp hive`) не правим. Он сам получит короткие id и облегчённые ответы
  (они формируются в hive), но продолжит слать pretty + structuredContent. Пользователь
  переключает Claude Code на встроенный `hive.exe mcp` (Settings → AI agents → Configure — жмёт
  пользователь, не мы).
- Протокол моста остаётся 1: входы обратно совместимы (полные id работают), старый сервер принимает
  любые строки как id.

## Анти-цели

- Агент путает объекты из-за коротких id (неоднозначный префикс молча указывает не туда).
- Агенту приходится делать больше вызовов, чтобы получить то же самое (например, ради имени).
- Короткий id меняется от вызова к вызову без причины.

## Подходы

- **B (выбран):** компактный ответ один раз + облегчённые формы ответов + короткие id,
  вычисляемые в hive. Максимальная экономия, id стабильны (это префикс UUID, без состояния).
- **A:** то же без коротких id. Проще, но UUID остаются самой крупной частью большинства ответов.
- **C (отвергнут ранее):** один файл доски вместо файла на объект — ломает совместную работу
  через Git и не уменьшает MCP-ответы.
- Рассмотрено и отвергнуто для id: нумерация на сессию (`n1`, `n2`) — нестабильна между
  сессиями и агентами, требует состояния на сервере.
- Рассмотрено и отвергнуто для списков: колоночный формат (`columns` + `rows`) — ещё ~25–30%
  экономии на `list_nodes`, но модели заметно чаще путают столбцы; надёжность важнее.

## Дизайн

### 1. Ответ один раз, компактно (Rust, `mcp_stdio/tools.rs`)

`ok()` возвращает только `content: [text_block(compact JSON)]`, без `structuredContent`
(у наших инструментов нет `outputSchema`, клиенты обязаны читать `content`). Перед сериализацией
общий проход по значению:

- дробные числа округляются до 2 знаков (целые и таймстемпы не трогаются);
- в объектах выкидываются поля со значением `null`, `[]`, `{}` — кроме ключей верхнего уровня
  ответа (`nodes: []`, `selection: []` остаются, чтобы «пусто» было явно).

`fail()` тоже компактный. Проход общий для живого режима и офлайна.

### 2. Короткие id (TS, новый `app/src/mcp/shortIds.ts`, подключается в `dispatcher.ts`)

**Вселенная id** — id живых нод, связей, зон, записей корзины и архива; `me` не трогается.

**Короткая форма** — самый короткий префикс длиной ≥ 8, уникальный во вселенной (через сортировку
и общий префикс с соседями). У UUID v4 первые 8 символов случайны; при ~1000 объектах совпадение
восьми символов — порядка 0,01%, тогда id становится длиннее (`a1b2c3d4-e`). id короче 8 символов
остаются как есть.

**Выход** — после выполнения метода каждая строка в результате (и в `data` ошибки), *в точности*
равная id из вселенной (до или после вызова), заменяется короткой формой. По значению, а не по
ключам: текст заметок никогда не совпадает с UUID целиком, а новые поля ответов не нужно
регистрировать.

**Вход** — до выполнения метода разворачиваются строки только под ключами `id`, `ids`, `nodeId`,
`zoneId`, `linkedTo`, `node`, `from`, `to` (в любом месте параметров), кроме поддерева `data`
и значений, равных `ref` этого же вызова (`create_nodes`). Правило:

- точное совпадение с id → без изменений;
- иначе, если длина ≥ 6 и ровно один id вселенной начинается с этой строки (без учёта регистра) →
  заменить на полный;
- если таких несколько → `invalid_params`: «Id '…' is ambiguous: matches …; use more characters»;
- если ни одного → оставить как есть (метод сам вернёт `not_found`).

Применяется ко всем клиентам моста, значит и старый Node-сервер получает короткие id.

### 3. Облегчённые ответы (TS, `app/src/mcp/*`)

- **`zones.list`** → `{ id, name, color, rect: {x,y,width,height}, nodeCount }`. Новые
  необязательные параметры: `members: true` — добавить `nodeIds`; `geometry: true` — добавить
  `parts`/`holes`. Те же поля возвращают `zones.create` / `zones.update`. Схема `list_zones` в
  `tools.rs` получает эти два параметра.
- **`nodes.list`** → без изменений набора полей, но: превью текста 80 символов вместо 160
  (новый параметр `preview`: 0–300, 0 = без превью); `linkCount` только если > 0; лимит по
  умолчанию 50 (max 500). Фильтр `zoneId` считает членство так же, как `zones.list` и поле
  `zoneId` в ответе (`zoneOf`), а не по сохранённому `note.zoneId` — сейчас они расходятся.
- **`nodes.move`** → `{ moved: N }`.
- **`nodes.arrange`** → `{ nodes: [{ id, x, y }] }` (позиции считает hive, агенту они нужны).
- **`nodes.update`** → `{ updated: [{ id, name, x, y, width, height }] }` (имя может получить
  суффикс, размер может стать авто).
- **Связи** (`links.list`, `links.create`, `links.update`, `links` в `nodes.get`) — `kind`
  не пишется, если `strong`, `shape` — если `base`; описания инструментов говорят об этом.
  Имена концов (`fromName`, `toName`) остаются — иначе агенту нужен лишний вызов.
- Остальное (`status`, `nodes.get`, `search`, корзина, архив, `board.overview`, `schema`) — только
  за счёт пунктов 1–2.

### 4. Офлайн (Rust, `mcp_stdio/offline.rs`)

Когда hive закрыт, читающие инструменты отвечают из файлов проекта. Там то же самое: короткие id
по вселенной загруженного проекта (порт алгоритма, новый `mcp_stdio/short_ids.rs`), развёртка
префиксов во входах `get`/`list`/`links`/`find`, облегчённые `zones` (+ `members`/`geometry`),
`list` с `preview` и лимитом 50. Компактность и округление — из пункта 1.

### 5. Тексты для агента

`INSTRUCTIONS` в `mcp_stdio/mod.rs` и описания инструментов в `tools.rs`: ids короткие, их
передают обратно как есть, полные тоже работают; `list_zones` без членов — используйте
`list_nodes {zoneId}` или `members: true`; умолчания `kind`/`shape` у связей. Контракт
`docs/handoff/d34_mcp_contract.md` обновляется под новые формы.

## Проверка

- Vitest: `shortIds` (уникальность префикса, удлинение при совпадении, развёртка, `ref` и `data`
  не трогаются, неоднозначный префикс → ошибка, полный id проходит), формы ответов методов.
- Rust-тесты: проход компактности (округление, выброс `null`/`[]`/`{}`, верхний уровень
  остаётся), офлайн-короткие id и развёртка.
- E2E на изолированной сборке (`dev.hive.cliptest`) и копии sidequest-kingdom-files в scratch:
  Node-клиент по stdio прогоняет `list_zones`, `list_nodes`, `list_links`, `get_nodes`,
  `move_nodes` (короткими id), `create_nodes` + `create_links` по ref, офлайн-чтение; таблица
  «было/стало» в символах. Configure не нажимается.
- `npm run check`, `npm test`, `cargo test`.
