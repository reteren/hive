# d42 audit c — interaction hot paths

Read-only audit of interaction, selection, history, navigation, and search code. Paths and line numbers are relative to `C:\hive`. No source was changed and no timings were measured; 10k costs below are static loop/read counts and complexity estimates.

## Hot paths

| 1 | Drag preview visits every registered board drop target. `previewDropTarget` calls `resolveDropTarget`, which walks the registry backward until a match. | `app/src/selection/SelectionLayer.svelte:1516,1553`; `app/src/selection/dropTargets.ts:40-42,61-69` | O(T) per animation frame, where T is mounted drop-target bodies; upper bound 10,000 callback calls/frame if T=10,000. ## Pointer-move trace: group drag of 50 notes

1. `onPointerMove` calls `localPoint` → `cachedClientRect` and `queueBoardMove`; that queue keeps the latest event and schedules one `requestAnimationFrame` (`SelectionLayer.svelte:696-724,1111-1120`; `board/boardRect.ts:31-42`). `localPoint` usually hits the rect cached during pointer-down; a miss reads one board `getBoundingClientRect`. Resize/scroll invalidates it.
2. The frame calls `runBoardMove` → `updatePointerGesture` → `screenToWorld` → `updatePrecisionDelta` → `crossedGestureThreshold` (`SelectionLayer.svelte:1138-1141,1451-1486`; `selection/precision.ts:26-41`; `selection/gestures.ts:24-26`). The first frame past threshold calls `beginMovingStacking` → `endMovingStacking`, then `querySelectorAll` + filter, `raiseMovingCards`, and `movingVisuals.setTargets` (`SelectionLayer.svelte:1484-1487,1999-2007`; `stats/movingCards.ts:2-18`; `selection/movingVisuals.ts:15-32`). This is the one-time O(V) scan. `querySelectorAll` does not measure layout; selected-card style/dataset reads and writes are O(50) and do not call `getBoundingClientRect`.
3. Every moved frame calls `updateMoveGesture` (anchor `.find`, optional `snapToGrid`, and `.map` over 50 frames), then `applyFrames` (50 iterations; `geometryFromListStatisticsFrame` + `updateNote`/`Object.assign` for each surviving note) (`selection/gestures.ts:286-313`; `SelectionLayer.svelte:1544-1554,1939-1968`). This path does not loop over `board.order` or serialize the board. Selection outline derivation may then project the selected IDs once per reactive flush (`:270-291`).
4. `updateModulePreview` returns immediately for a multi-selection (`SelectionLayer.svelte:2095-2101`). `previewDropTarget` maps the 50 IDs → `resolveDropTarget` scans T registered targets → each current `accepts` returns at its single-ID guard → `activeDropTarget.set(null)` (`dropTargets.ts:40-42,61-69`; e.g. `combo/ComboHost.svelte:35-36`, `list/ListBody.svelte:82-85`, `tierlist/TierlistBody.svelte:249-250`, `audio/AudioNodeBody.svelte:40-41`). Thus recurring work is O(50 + T) calls, not O(10,000) note geometry work; there are no target DOM rect reads for this 50-note case.
5. On release, `moveGestureChange` compares/copies affected frames and `geometryHistoryCommand` captures before/after arrays for Undo/Redo (`selection/gestures.ts:217-232,466-485`). `applyFrames` replays those arrays; this is O(S), not a whole-board snapshot. The stack stores commands, not board snapshots (`history/historyStack.ts:22-47`).

## Wheel-zoom trace

`cameraInput.onWheel` → `updatePointer` → `localPoint` → `cachedClientRect` → `setPointerScreen` → `refreshPointerWorld` → `screenToWorld`; then `wheelDeltaScale` → `zoomAt` → camera field assignments → another `refreshPointerWorld`/`screenToWorld` (`board/cameraInput.ts:38-41,174-188,260-263`; `board/camera.svelte.ts:39-47`). Cost in this path is O(1), with no note loop. A rect cache miss reads the board rect; page-mode input reads `clientHeight`. SelectionLayer recomputes screen-space outlines for selected IDs on camera changes, O(S), not O(N) unless most/all notes are selected. Other camera-dependent render layers are outside area c and need review by their owners.

## Proposed fixes

- **Drop preview fan-out:** Skip preview resolution for multi-note drags while every registered target rejects groups. Longer term, store target world bounds in an indexed registry; query only nearby candidates, then perform exact target checks. Add a cheap model-bounds rejection before List/Tierlist DOM measurements, and cache board/target rects for the current frame. Files: `selection/SelectionLayer.svelte`, `selection/dropTargets.ts`, `list/ListBody.svelte`, `tierlist/TierlistBody.svelte`, and target body registrations. Risk: a coarse model box must include dynamic auto-height/list extensions and row hit areas or it could reject a legitimate drop. Gain: group preview becomes O(1); single-note preview becomes O(log T + nearby candidates) with layout reads limited to likely targets.
- **Point/marquee hit tests:** Add a world-space spatial index, preferably an R-tree or a grid hash with an overflow path for very large objects. Use it to get point/marquee candidates, then preserve exact bounds/shape tests and sort by `board.order` for paint-order semantics. Update entries incrementally on add/remove/geometry changes, including the 50 moved notes, rather than rebuilding on every frame. Files: `selection/hitTesting.ts` plus the board model/geometry mutation boundary; coordinate the zone index with the links/zones owner. Risk: stale entries or wrong z-order can change selection behavior. Gain: queries approach O(log N + K) instead of O(N).
- **Search indexes:** Keep normalized name/kind/text search data per note and update only the edited note; avoid rebuilding order maps twice per query. Apply the same index to Objects-panel name filtering, keeping current creation/paint ordering as explicit sort keys. Files: `search/SearchPanel.svelte`, `search/matching.ts`, `search/search.svelte.ts`, `navigation/ObjectsPanel.svelte`. Risk: Unicode/diacritic folding, snippets, and result ordering must remain identical. Gain: query work depends on changed/index-matched text rather than rescanning all note text.
- **Drag-start card lookup:** Maintain an ID-to-mounted-element registry in the note layer and collect selected mounted elements by ID, or apply stacking changes through selected IDs directly. Files: `selection/SelectionLayer.svelte` and the node component registry owner. Risk: unmount/culling must unregister safely; only mounted cards can receive visual stacking styles. Gain: O(S) lookup instead of O(V) scanning at drag start.
- **Large-selection outlines:** Use the shared visible set to project/render outlines only for visible selected notes while computing the functional group bounds from the complete selection. Keep selected IDs and off-screen movement semantics independent of rendering. Files: `selection/SelectionLayer.svelte` and the shared visibility service. Risk: selection borders should reappear immediately on pan/zoom and not affect group handles. Gain: outline projection/render work follows visible selected count.

## Culling / LOD contract

- Selection needs `queryPoint(worldPoint)` and `queryRect(worldBounds)` over all model geometry, returning candidate IDs. The index must not be derived from mounted DOM: off-screen selected notes still move, and search/navigation must still resolve unmounted IDs.
- Return exact candidate IDs with a board-order key; selection applies existing rounded-note and zone-shape predicates after broad-phase lookup. Keep note/beacon and zone geometry available to their respective hit tests.
- Update the index after model add/remove/resize/move; batch the 50 position updates within the drag frame. Camera pan/zoom changes the viewport query only and should not rebuild world geometry.
- Drop-target preview needs a point query over registered target bounds, with target-specific exact checks only for returned candidates. A shared visible set is useful for DOM affordances, but it must not silently remove off-screen model objects from selection or history.
- LOD affects what a node body renders, not which object its ID, bounds, selection, keyboard command, or search result refers to.

## Quick wins (≤30 lines each)

- Skip `previewDropTarget` for multi-ID moves while the current registered target implementations keep their single-ID guard.
- Add model-space broad-phase rejection to List/Tierlist targets before calling layout-sensitive DOM rect methods.
- Cache parsed command bindings in `findMatchingCommand`; its keydown work is O(C × bindings), but C is the fixed command registry and is not the board-size bottleneck.

## Structural changes

- Add and maintain a shared spatial index for note/beacon/zone hit and marquee queries.
- Replace the drop-target full registry sweep with indexed target bounds and frame-scoped exact geometry.
- Add per-note normalized search indexes and update them on content changes.
- Add a mounted-note element registry and viewport-filtered selection-outline projection.

## Open questions

- Is multi-note drop intended to remain unsupported for all targets? The currently registered audio, combo, List, and Tierlist targets reject any ID list whose length is not one; if that is a stable contract, skipping group preview is safe.
- Should the spatial index own zones too, or should selection delegate zone candidate queries to the links/zones workstream?
- Should Objects-panel filtering preserve alphabetical/recent sorting over all matches, or can it use virtualized results once the query index is added?
