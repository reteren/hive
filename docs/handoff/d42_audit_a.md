# d42 audit a — Node rendering pipeline

Static source audit only. I did not launch Hive, open a project, run tests, or take runtime measurements. Counts below are source-derived; elapsed costs are estimates. For cardinality estimates, N means non-beacon notes, V video notes, Y YouTube notes, T Time notes, E links, and Z zones.

## Culling / LOD contract

- Inputs: camera center and zoom, viewport size, note bounds including scale and list-statistics extension, and a screen-space overscan margin. Update on camera/zoom/viewport changes and note geometry changes, coalesced to at most once per animation frame; query a spatial index instead of scanning board.order.
- Outputs: stable visible IDs, plus a pinned-ID set for selected, actively edited, focused, dragged, pointer-captured, popup-target, and search/MCP-target notes; a LOD tier per ID; and cached bounds/height for geometry consumers.
- LOD starting rule: at zoom >= 0.3, visible notes use full bodies. From 0.1 to 0.3, show card color, kind/title, and selection affordances while suppressing Markdown parsing, media surfaces, and controls. Below 0.1, show a plain colored rectangle; include a short label only when its projected footprint can fit it. Use projected size as well as zoom so large/scaled notes remain legible.
- Height ownership: measuredHeights is currently written by visible DOM observers and deleted when the action is destroyed (NotesLayer.svelte:170-210). Move the persistent metric cache outside the action lifecycle; use a deterministic estimate for never-measured notes and preserve last-known measured height for culled notes.
- Interactions: link paths, hit testing, and navigation should use model bounds, not require endpoint DOM. Current link/navigation/MCP geometry calls noteBounds. Keep selected/editing IDs mounted while a gesture or focus requires their DOM; otherwise selection and hit testing remain model-based.
- Search and go-to: teleportToObject uses model bounds and selects the target (navigation/navigate.ts:88-101); recompute visibility after the camera jump and pin the target until the user leaves or changes selection.
- MCP: board.overview is model-based. view.capture computes model bounds, changes the camera, waits for rendering, then captures the board (mcp/view/capture.ts:38-43); the culler must publish the new visible set before waitForBoardRender completes and must include all fitted/requested capture IDs.
- Markdown currently has a partial LOD: MarkdownPreview renders source text until first intersection, then parses Markdown and creates inline image/GIF components; its visible flag never turns false (MarkdownPreview.svelte:87-119). Restoring plain text on exit can release that subtree, but a shared visibility service should own the consistent policy.
- Cross-layer caveat: the note selection/hit-test code queries model bounds and some operations query DOM bodies. Culling should preserve data-driven geometry and pin the DOM only for operations that truly need it.

## Quick wins (each intended to stay within 30 changed lines)

- MarkdownPreview: set visibility from the latest IntersectionObserver state, not only set it to true. This releases parsed Markdown and inline media after leaving the viewport. Add a small overscan/hysteresis margin to avoid rapid toggling.
- Fix the text-width measurement call path: either write its returned width into the cache that resize consumes or remove the width computation from the height observer when it has no consumer. Verify the intended fit-width behavior before removal.
- Keep the existing PDF per-page IntersectionObserver; avoid adding another observer per page or eager canvas rendering.

## Structural changes

- Shared spatial index, visible set, and LOD service with note-metric cache independent of DOM lifetime.
- Separate lightweight note shell from heavy body mount, with lifecycle hooks for media/timers and pinned interaction targets.
- Per-note adjacency index for linked module styling; incremental zone membership updates.
- Keyed DOM/metric registry for the few interactions that need live element geometry.

## Open questions

- Should low-zoom labels use node name, node kind, or both? At zoom below 0.1, should any label render only when its projected footprint exceeds a fixed pixel threshold?
- Which node kinds must remain active off-screen (playing media, recording, active timer, open editor)? These should be explicit pinned lifecycle states.
- Is the ignored result from measureAndCacheTextMinimumWidth intentional? Its minimumTextWidth result is not stored, and cacheMinimumTextWidth currently has no call sites.
- Coordinate the zone-membership O(N) drag dependency with the owner of zones; it is outside this letter’s primary files.
- Source reactivity interpretation follows Svelte’s documented deep $state proxies and synchronous $derived dependency tracking: [Svelte $state](https://svelte.dev/docs/svelte/$state) and [Svelte $derived](https://svelte.dev/docs/svelte/$derived).
