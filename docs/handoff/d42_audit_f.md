# D42 Audit F — Heavy content and per-node cost

## Scope and estimate basis

Static, read-only inspection of `app/src`; no app/project was opened and no runtime benchmark was run. All figures below are estimates, not measured performance. Memory examples count only uncompressed pixel/text payloads and omit framework, DOM, GPU, browser cache, and allocator overhead.

The shared multiplier is that `NotesLayer` iterates every ordered note and mounts `NoteNode` for every non-beacon (`notes/NotesLayer.svelte:228-232`); `NoteNode` selects and constructs each kind's body (`notes/NoteNode.svelte:268-309`). There is no app-level viewport or zoom gate at these two boundaries. Content bodies therefore keep their normal work and resources while their note is outside the board viewport.

## Hot paths

### Additional per-node observations

- `ListBody` recalculates statistics for all rows when its inputs change; beacon rows count connections by scanning all links (`stats/listStatistics.ts:41-59,138-144`). Worst case is O(beacon rows × links) for a statistics-enabled List on a link change. The row cache avoids recounting text but connection counts are computed before cache lookup.
- `SourceNodeBody` debounces file-availability checks and uses a shared path cache, so its ordinary idle cost is low (`source/SourceNodeBody.svelte:44-72`; `source/logic.ts:44-77`). It presents a URL/path rather than embedding a live webpage.
- Calculator bodies recompute their own entry list when calculator data changes; cost is O(entries) per affected calculator and there is no polling (`calculator/CalculatorBody.svelte:9-12`).
- Spellcheck is scoped to instantiated CodeMirror plugins and schedules checks over `view.visibleRanges`, not every note body (`spell/spellcheck.ts:232-240,294-312`). Normal note CodeMirror mounts only for the currently edited note (`editor/NoteBody.svelte:33-49`). Format nodes are the exception noted in #2.
- Absolute Importance and multi-colour custom-mark frames use infinite CSS background animations; note glow adds blurred box shadows (`modules/modules.css:25-43,371-394`; `notes/NoteNode.svelte:176-177,340-342`; `notes/noteGlowLogic.ts:55-63`). These are paint/compositing costs on marked cards and have no board-visibility pause. Change marks add static pseudo-element ring/label only to marked nodes (`notes/NoteNode.svelte:575-609`); the edit-time clock is one shared interval, not one timer per card (`changes/changeMarks.svelte.ts:168-178`).

## Proposed fixes

1. **Images and GIFs:** Have import/persistence produce bounded display thumbnails; load the original only when visible, selected, or at sufficient screen size. Run transparency checks only on demand or from import metadata, and cap/release decoded bitmap/canvas caches. Touch `attachments/*`, `images/*`, and attachment import/storage code. Risk: thumbnail generation/storage migration and briefly lower detail while zooming in. Expected gain: replace full-size off-screen decode and scan with a small bounded preview.
2. **Format and PDF:** Construct Format CodeMirror views only when visible or explicitly opened for editing; keep unloaded text as a lightweight summary. Defer PDF document/page acquisition until the containing note is near the viewport, virtualize page placeholders while preserving scroll height, and cap retained page proxies. Touch `formats/FormatNodeBody.svelte`, `PdfNodeBody.svelte`, and PDF scheduling. Risk: first-open delay, scroll-anchor/page-height bugs, and changes to always-editable Format behavior. Expected gain: startup memory/work proportional to active documents and visible pages.
3. **Audio, video, YouTube:** Keep media sources unset or `preload="none"` until an explicit play or near-viewport intent; pause and release decoded media when a note leaves the active set. Keep YouTube as a thumbnail until play, then pause/unmount its iframe when off-screen; deduplicate metadata and thumbnail work by video ID. Delegate pointer capture to one shared listener. Touch `audio/*`, `video/*`, `youtube/*`, plus the shared visibility/media controller. Risk: additional first-play latency and deciding whether off-screen playback should continue. Expected gain: fewer metadata/network starts, listeners, decoders, and live iframe processes.
4. **Time and Message:** Build a shared adjacency index and board-order index keyed by graph/order revisions; resolve each Message/Time node from its neighbors rather than copying/scanning all edges and notes. Replace per-Time-body interval with a shared clock subscription; preserve the app-wide scheduler's checks independently of rendered visibility. Touch `messages/resolution.ts`, `MessageNodeBody.svelte`, `time/taskLink.ts`, `TimeNodeBody.svelte`, and shared time state. Risk: index invalidation correctness and countdown UI update timing. Expected gain: O(degree) per relevant node instead of O(notes + links) per Message and one UI timer instead of one per Time body.
5. **Map:** Share one immutable minimap snapshot/frame among MapViews; update it from board/camera revisions and render map bodies only when near-visible. Keep the existing link limit but avoid copying all links above it. Touch `map/MapView.svelte`, `map/mapMath.ts`, and a shared map-frame store. Risk: frame staleness during drag and synchronization between multiple map surfaces. Expected gain: one board scan per update instead of one per Map node.
6. **Markdown and collections:** Skip link parsing for off-screen previews, use incremental/cached link resolution, and apply a text LOD at far zoom. Virtualize long List/Tierlist collections while retaining stable row/card geometry for drag, insertion, and keyboard navigation. Make the tierlist video-frame cache LRU-bounded and clear evicted canvases. Touch `editor/MarkdownPreview.svelte`, `editor/markdown.ts`, `list/*`, `tierlist/*`. Risk: drag/selection behavior and estimated heights for unmounted rows; keep placeholders for layout. Expected gain: less parser work, DOM, remote imagery, and retained thumbnail memory.
7. **Decorations:** Pause gradient animation and simplify glow/shadow at far zoom or outside the active set. Touch `modules/modules.css`, `notes/NoteNode.svelte`, and the shared visibility/LOD consumer. Risk: reduced visual fidelity while distant. Expected gain: fewer animated backgrounds and blur paints on large boards.

## Culling / LOD contract

- Inputs: stable note ID/type, world bounds including note scale, camera transform/zoom, viewport size, and device pixel ratio. Update on camera/viewport changes and indexed note-bound changes, not by making each body rescan the board.
- Outputs: stable state per note/body: `visible`, `prefetch` (viewport plus configurable margin), or `culled`; include a screen-pixel size/LOD bucket and a target backing resolution capped by a global pixel/memory budget. Use enter/exit hysteresis to avoid thrashing at edges.
- Heavy bodies consume the state: visible image uses a resolution-matched thumbnail or original; prefetch loads bounded thumbnail/metadata; culled image releases decoded surfaces. PDF pages expose their own page-visible set within a visible document. Audio/video start only from explicit playback intent, pause on cull, and retain enough state to resume. YouTube iframe exists only during active playback. Text preview may show title/summary at far zoom; CodeMirror exists only for active editing/open Format.
- Visibility must not control semantic state: timers, persistence, links, search targets, selections, and node dimensions remain available while their visual body is culled. Preserve lightweight stable placeholders/bounds for navigation, hit testing, drag, and internal scroll layout.

## Quick wins (each change can stay within ~30 lines)

- Add bounded LRU eviction to `tierlist/videoPreview.ts`; clear a released canvas before dropping it.
- Change audio/video metadata preload to `none` and promote to metadata/load only at explicit interaction, if browser behavior supports the current playback flow.
- Deduplicate YouTube metadata promises by video ID and avoid fetching before a preview approaches the viewport.
- Replace the per-Time-body 1-second interval with one shared `now` notifier in the time runtime.

## Structural changes

- Shared viewport/LOD service and lifecycle contract for note bodies and child media.
- Thumbnail/downsampling pipeline and explicit raster/page/media budgets with eviction.
- Indexed graph adjacency and shared map frame snapshot.
- CodeMirror-on-demand for Format nodes; virtualized PDF pages and long List/Tierlist collections.

## Open questions

1. At what rendered size should images, PDFs, text, and marked frames change to a title/thumbnail/shape, and what zoom thresholds should the shared LOD service use?
2. Should a video or audio player pause automatically when its note leaves the viewport, or is continued background playback expected?
3. Is a Format node meant to remain directly editable at all times, or can it open CodeMirror on selection/edit intent?
4. How much preview detail should remain available for PDF pages and tierlist cards while their source note is off-screen?
