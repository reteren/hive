# hive — реестр нод и их готовности

На вопрос **«какие ноды ещё есть / какие остались?»** отвечаем по этому файлу: что уже работает, что сделано частично, что следующее, что отложено. Это список выбранных возможностей, а не предложение новых идей и не задание реализовать всё сразу.

## Что уже есть в приложении

**Реализованных нод пока нет. В работе по коду — тоже нет.** В текущей папке находятся описания и планы, а не реализация приложения. Наличие ноды в этом реестре или roadmap не означает, что она работает.

Готовность: **Не начато → В работе → Частично → Готово**. Отдельно указывается очередь разработки. «Дальний ящик» — очередь, не отказ от идеи. «Условно» и «не решено» — степень согласия, не готовность.

Источники: [исходник](hive.md), [заполненный первый опросник](QUESTIONS_AND_IDEAS.md), [текущие уточнения](FOLLOWUP_QUESTIONS.md). Новейшие явные ответы важнее старых описаний. Номера N/M/E — из первого опросника, H — из уточнений; «идея №…» — твой список в конце первого опросника.

Очереди R — [ROADMAP.md](ROADMAP.md). Причины отсрочек и отклонённые варианты — [LATER.md](LATER.md). Названия новых пользовательских механик ниже описательные: это не утверждение окончательных английских названий кнопок.

**Importance и Purpose можно вставлять в текстовые ноды, задачи, плюсы и минусы.** H12 отдельно отвечает «да» для перечисленных мини-нод, калькулятора и Tierlist: рабочее прочтение — расширение более узкого вступления, поддержка добавляется вместе с типом. Это не разрешение модулей у любых неперечисленных типов. H11 разрешает несколько Purpose; ограничение одной Importance остаётся.

Плюсы/минусы могут иметь много родителей и потомков, направление связи допускается любое (H15). Между конкретной парой всё равно одна линия (H25). При удалении родителя мини-ноды остаются, удаляется только связь (H16).

### Режимы, которые не считаем отдельными типами

- **Importance:** basic / medium / important / immediately / 100% — белый / жёлтый / красный / фиолетовый / радужный. Дополнительное действие уровня 100% отложено, не выдумано за тебя.
- **Purpose:** Quote / цитата; Concept / понятие; Open Question / открытый вопрос; Decision / решение; Hypothesis / гипотеза; Experiment / эксперимент; Compare / сравнение; Timeline / лента событий. Это восемь визуальных меток, а не восемь специальных редакторов.
- **Плюс/минус:** два варианта одной семьи мини-нод. Разделены в реестре, чтобы оба были видны; это не требование двух независимых реализаций.
- **Task-флаг** и **живая передача текста из заметки в task** не создают дополнительные типы нод. По свежим H09–H10 текст обновляется вместе с источником, замена имеющегося текста требует вопроса пользователю. Старое указание на отдельный «центр текстового поля» больше не является правилом подключения.

- Table — Markdown-таблица; Milestone/Formula/Measure не дублируют **Goal/калькулятор/статистику**.
- Field Changed из N036 заменена **историей активности**, а не событием изменения свойства.
- PDF из N081 заменена **Format**; Calendar Link из N086 — твоей **календарной нодой**, не внешней синхронизацией.
- Export/File, Task State Changed, On Error и Queue как отдельные ноды не нужны. Экспорт, вложения, изменение состояния, ошибки и очередь сообщений при этом остаются функциями программы.
- Archive сохранена именно как твоя нода просмотра архива, не как прежнее действие автоматизации.
- N033 Units-конвертер отклонён. Единица координат **юнит (u)** от этого не исчезает: это мера на доске, не вычислительная нода.

## Как поддерживать список актуальным

1. Перед ответом о готовности сверять реестр с текущим кодом и проверками. При расхождении сообщать его, не выдавать старую отметку за факт.
2. При начале реализации конкретной ноды менять готовность её строки на «В работе»; для строк дальнего ящика добавлять явную готовность рядом с решением или переносить в основную таблицу, сохраняя ID.
3. «Частично» всегда сопровождать списком: **работает / ещё отсутствует**. Например, импорт Audio не равен готовой записи с микрофона.
4. «Готово» ставить только после проверки заявленного объёма. Рядом указывать ссылку на код/проверку и дату. Каркас, макет и заглушка не считаются готовой нодой.
5. При новом решении обновлять эту запись, не создавать её дубликат под старым и новым названием. Режимы и встроенный/внешний вид одной ноды не раздувают число типов.
6. В ответе пользователю сначала давать **готовые / частичные / ближайшие оставшиеся**. Дальний ящик и неопределённые варианты показывать отдельно, без вывода всей старой книги по умолчанию.

ID ND/MAY постоянные; их числа — номера записей, **не количество уникальных программируемых типов**. Новые ответы добавляют правила, но сами по себе не меняют готовность реализации.
